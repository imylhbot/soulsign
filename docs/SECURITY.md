# SoulSign security rules

- Never commit Apple ID passwords, 2FA codes, session cookies, private keys, p12 files,
  pairing files, or provisioning secrets to GitHub.
- Keep account secrets in the iOS Keychain. SoulSign relies on the upstream account
  repository/Keychain model and does not add plaintext credential persistence.
- Automatic/background renewal must reuse saved sessions. If Apple requires new 2FA,
  background renewal should fail safely and let the user re-verify interactively.
- The 3-app-per-ID rule in SoulSign is an app-level scheduling policy. Apple can impose
  additional free-development limits (including bundle IDs/extensions/certificates).
- Release artifacts generated by GitHub Actions are unsigned by default.
